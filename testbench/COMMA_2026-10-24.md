# 2026-10-24：Ctrl+, 逗號組字修復

已部署目前使用者版本：`959055bce9d35c897d49a9ffad0ea631daf73881a0d68e5a76d994034eea6971`。

## 問題與原因

症狀為逗號沒有組字底線，繼續輸入的中文字出現在逗號左側。隔離測試直接呼叫 `VK_OEM_COMMA` 時原本已正常，但記事本實測仍重現。

對獨立測試記事本的實際回呼追蹤顯示，Ctrl+, 可以送進 `VK_PACKET`（231），lParam 為 `0x1`；原程式僅處理實體 OEM 逗號鍵，直接放行這個 Unicode 事件。因此逗號由宿主先插入文件，原本尚未提交的整段組字隨後插到它後方。

Windows 對這類輸入提供 `ToUnicode(VK_PACKET, 0, keyboard_state, ...)` 取字方式；字元不在此處的 lParam 掃描碼內。參照 [Microsoft IME 輸入要求](https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements)。

## 修改

- `tsf/text_service.cpp` 解碼 Unicode 按鍵封包，將標點納入相同的組字與 FIFO 寫入路徑。中文模式的 Ctrl+ASCII 標點套用現有全形標點映射。
- 空閒時僅讓標點啟動組字；已完成轉換的一般 Unicode 文字保持原有輸入方式。單獨的 UTF-16 surrogate 保留由 Windows 組合，避免各半轉成替代字元。
- 保留大千鍵盤直接逗號鍵的「ㄝ」功能、中英混合組字，以及既有標點候選清單。
- 檢查最新來源時，另發現 Backspace 有兩個相同條件的連續分支，前一分支擋住了已組字內容的刪除；移除重複分支，並在 Shift 丟棄注音時清空元件輸入順序。這項回歸由既有 TSF input 測試偵測。
