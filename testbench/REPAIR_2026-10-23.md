# E-IME 宿主崩潰修復與驗證

受測／目前使用者已部署 DLL SHA-256：`ec71fc3f835de55391d047d2acc313fc62e15f9a61628c464829ac1c945dce52`。
部署位置為 `%LOCALAPPDATA%\E-IME\versions\<SHA-256>\E-IME_tip.dll`，目前使用者的 COM override 指向這份版本，語言設定檔已重新啟用。HKLM 原有註冊仍保留；此輪未變更其他使用者設定。

## 證據與修復

- 舊 DLL 的顯示屬性物件／列舉器仍由外部持有時，`DllCanUnloadNow` 已回傳 S_OK。新增測試在舊版本確實失敗；現在所有這類 COM 物件均計入模組生命週期，並釋放列舉器建構時多餘的初始參考。
- 模擬宿主在 EndComposition 內重入終止回呼時，舊 DLL 在 execute_edit_session 發生 SIGSEGV。現在先移出 composition_，再呼叫宿主及釋放，避免回呼再次釋放成員。這是隔離回歸測試的重現，不能單憑它認定所有先前應用程式崩潰皆是同一原因。
- 候選視窗改用各實例專屬 class，銷毀時 UnregisterClass，WM_NCDESTROY 清除物件指標，避免 DLL 卸載後留下視窗程序位址。
- 停用／重新啟用增加 generation 檢查，舊的延遲 edit session 不再修改新一次啟用的文字或建立 UI。
- 原新產物依賴未部署的 libwinpthread-1.dll；恢復 MinGW 靜態連結，發行版匯入表僅剩 Windows 系統 DLL。
- 安裝改用 SHA-256 版本目錄，禁止覆寫既有 DLL。data-root.txt 以 UTF-8 指向原專案 data，保留中文路徑、詞庫與同步日誌。資源初始化失敗透過 COM HRESULT 回報。
- 舊按鍵注入腳本不再註冊編譯目錄 DLL，另寫 legacy_key_injection_report.json，避免覆蓋真正實測報告。它仍只是送鍵腳本，不能作為 PASS 證據。

Explorer 傾印顯示當時在 ntdll 載入器內處理 E-IME，並非這次隔離重入測試的相同堆疊。暫停新載入後，Explorer 恢復穩定。實機驗證期間查詢 Application Error 1000，未發現新增事件。未強制結束其他使用者應用程式，仍載有舊 DLL 的既存宿主須待正常結束後才會完全釋放它。

## 後續使用

正常編譯仍可使用 `cmake --build build`。安裝使用 PowerShell 7：`./scripts/install.ps1`；會複製到新的版本目錄再註冊。已有機器 TSF 註冊時，可用 `-UseExistingRegistration` 僅切換目前使用者版本。自訂產物位置用 `-SourceDll <absolute-path>`。

新測試目標：`E-IME_tsf_lifecycle.exe <absolute-DLL-path>`。核心測試可設定 `E-IME_TEST_DLL` 選擇受測 DLL；從具有 data/ 的測試工作目錄執行。此輪編譯與測試工作目錄在本機暫存區，避免覆寫已註冊的舊 build/ 產物。

需要暫停新宿主載入時，執行 `./scripts/disable.ps1`，不需管理員權限；重新執行安裝腳本即可恢復。它不能移除既存程序已載入的 DLL。

參照：[Microsoft DllCanUnloadNow](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-dllcanunloadnow)、[組字終止回呼](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcompositionsink-oncompositionterminated)。
