## [v0.4.0] - 2026-10-24（主線私人預覽）

### 發布準備與同步修復
* 每個輸入法實例改用獨立 writer 日誌，修復同機多宿主漏算及重複計算。
* 以每份日誌內各詞的累計值合併新增量，修復壓縮及較舊雲端快照造成的重算；半行紀錄延後至完整換行後再讀。
* 日誌壓縮改為暫存檔替換；寫入失敗不更新學習權重，過大權重採飽和計數。
* 新增同步回歸測試、隔離 CTest 測試資料及 Windows MSVC／MinGW CI。
* CMake 版本統一為 0.4.0；MSVC 加入 UTF-8 與靜態 CRT 設定。
* COM DLL 匯出改由 `.def` 定義，函式使用與 Windows SDK 一致的 `STDAPI` 宣告，修正 MSVC 的 C2375 連結屬性衝突。
* MinGW 連結使用建置目錄內的相對 `.def` 路徑，保留中文專案路徑支援；對將預設浮點環境移至 `libmingw32` 的新版 CRT，提前引入該符號以支援靜態連結 DLL。
* 補齊 LGPL 2.1、GPL 2.0、Apache 2.0 授權與 OpenCC 作者聲明；資料產生器固定上游 commit，並可重建比對。
* 名稱更新腳本改呼叫正式安裝器，移除本機版本雜湊與 Windows PowerShell 5.1 依賴；部署腳本檢查編譯失敗。

### 1. 微軟經典淺色風格候選字視窗 (Native Microsoft Light Theme UI)
* **視覺升級**：
  * 背景改用微軟原生經典純白 `#FFFFFF`，外框採用精緻細灰 `#DADCE0`，搭配 Windows 11 系統級 DWM 圓角（Preference = 2）與抗鋸齒投影（`CS_DROPSHADOW`）。
  * 選中項改用 Windows 11 現代淺藍膠囊高亮 `#EBF3FC`，並於左側呈現微軟藍經典識別條 `#0067C0`。
  * 候選字文字改用高對比深黑 `#000000` 與 `#202020`，序號（1~9）選中時顯示微軟藍 `#0067C0`，未選中時顯示清晰中灰 `#737373`。
  * 頁尾狀態標籤改用優雅灰 `#828282`（簡體模式為溫潤琥珀 `#B45309`）。

### 2. 快速打字順序錯亂高穩健性與提早中斷錯誤 (Out-of-Order Robustness & Early Typo Cutoff)
* **按鍵亂序自動歸位**：
  * 針對快速打字時聲母、介音、韻母落鍵順序錯亂（如 `u`+`0`+`w` -> ㄧ+ㄢ+ㄊ），在按下聲調鍵之前持續自動歸入正確音節槽位，維持標準 `[聲母][介音][韻母]`。
* **嚴格拒絕第 4 個注音符號**：
  * 單一漢字音節最多僅包含 3 個注音符號（1 聲母 + 1 介音 + 1 韻母）。當音節槽位已滿 3 個符號時，選字前嚴格拒絕任何非聲調的第 4 個注音鍵，立即響鈴並攔截，防止無限連打造成錯誤雪崩。
* **同類型重複槽位即時攔截**：
  * 音節中已存在聲母時拒絕第 2 個聲母，已存在介音時拒絕第 2 個介音，已存在韻母時拒絕第 2 個韻母。
  * 移除舊版的「聲母無聲調提早自動斷字」推測行為，確保必須由使用者按下聲調鍵（空白、6、3、4、7）才確定結音選字，大幅減少打錯字時需要按大量退格鍵（Backspace）的困擾。
* **標準大千鍵盤聲調映射**：
  * 一聲：`Space`（空白鍵）
  * 二聲（ˊ）：`6`
  * 三聲（ˇ）：`3`
  * 四聲（ˋ）：`4`
  * 輕聲（˙）：`7`
  * （注意：`1` 與 `2` 為聲母 `ㄅ` 與 `ㄉ`，非聲調鍵）

## [v0.3.0] - 2026-10-24

### 1. 注音符號先後順序智慧重組 (Bopomofo Syllable Permutation)
* **問題現象**：
  * 使用者打字時若先按韻母（如 `k` = `ㄜ`）再按聲母（如 `2` = `ㄉ`、`x` = `ㄌ`、`1` = `ㄅ`），舊版會將 `ㄜ` 提前結合成獨立一聲音節輸出（選中首字「婀」），後面的聲母作為下一音節起點，造成螢幕上出現「婀ㄉ」、「婀ㄌ」、「婀ㄅ」的重大異常。
* **原因分析**：
  * 舊版狀態機在收到聲母按鍵時，若當前音節已有韻母，會直接強制將前段音節以一聲送入組字區（Viterbi 解碼出「婀」），導致非預期的音節截斷與硬猜字。
* **修復方案**：
  * **按鍵亂序自動組合**：修改 `engine/include/input_state_machine.h`，在單一音節未完成前，聲母、介音、韻母無論以何種順序鍵入，均智慧歸入對應欄位，並由 `Syllable::to_string()` 自然按標準 `[聲母][介音][韻母]` 呈現（例如 `k` + `2` -> `ㄉㄜ`、`k` + `x` -> `ㄌㄜ`、`k` + `1` -> `ㄅㄜ`）。
  * **聲調選字對齊**：
    * `ㄉㄜ` + `7`（輕聲）-> 輸出高頻字「**的**」。
    * `ㄌㄜ` + `7`（輕聲）-> 輸出高頻字「**了**」。
  * **無對應字嚴格保底**：
    * 對於中文語音規範中不存在漢字的組合（如 `ㄅㄜ` 空白一聲、`ㄌㄜ` 空白一聲），Viterbi 保底輸出原生注音符號（如 `ㄅㄜ`），絕不隨機匹配同音或生僻字，與微軟新注音行為完全一致。
  * **無聲調連打自動切分**：
    * 當前音節已具備完整字身（有韻母或介音，或是獨立聲母 `ㄓㄔㄕㄖㄗㄘㄙ`）時，若再按入新聲母，自動將前一音節以一聲完成並啟動下一音節（如 `rupwu0` + 空白鍵流暢輸出「今天」）。
  * **Backspace 順序回退**：
    * 新增 `component_order_` 記錄實際按鍵順序。例如先按 `k` 再按 `2`，按下 Backspace 時優先撤銷剛按下的 `ㄉ`，保留 `ㄜ`。

### 2. 標點符號組字區虛線底線與候選清單展開 (Punctuation Composition & Candidate Selection)
* **問題現象**：
  * 使用者單獨輸入 `Ctrl+,`（逗號）或在句中鍵入標點時，標點符號沒有組字虛線底線，直接跑到游標最右側，且無法按向下鍵展開候選選取頓號等符號。
* **原因分析**：
  * 舊版在處理 `Ctrl+,` 等標點時，曾直接作為 commit 輸出至宿主程式，破壞了進行中的組字範圍。
  * `open_candidates_at_cursor()` 內部曾有 `if (!literal_texts_[candidate_target_idx_].empty()) return;`，將標點符號的候選展開全面阻斷。
* **修復方案**：
  * **組字區 Literal 槽位**：標點符號統一放入 `literal_texts_`，在 TSF 中持續享有 `atom_input_` 虛線底線屬性，維持整句組字狀態，游標緊隨其後。
  * **標點候選映射庫 (`ZhuyinParser::get_punctuation_candidates`)**：
    * 逗號 `，` -> `{"，", "、", "﹐", ","}`
    * 句號 `。` -> `{"。", "．", ".", "｡"}`
    * 問號 `？` -> `{"？", "?", "﹖"}`
    * 驚嘆號 `！` -> `{"！", "!", "﹗"}`
    * 冒號 `：` -> `{"：", ":", "﹕"}`
    * 分號 `；` -> `{"；", ";", "﹔"}`
    * 引號 `「` `」` -> `{"「", "『", "“", "‘", "\"", "'"}`
    * 括號 `（` `）` -> `{"（", "(", "〔", "【", "《", "〈", "{"}`
  * **選字行為對齊**：
    * 游標停留在標點處按 `向下鍵 ↓`，立刻彈出標點候選視窗。
    * 若為單個標點，選取候選後直接確認上屏；若為句中標點，選取後原地替換並保留組字區繼續打字。
  * **快捷鍵擴充**：
    * 支援 `Ctrl+'`（引號鍵）直接輸入頓號「、」，符合微軟新注音經典習慣。
