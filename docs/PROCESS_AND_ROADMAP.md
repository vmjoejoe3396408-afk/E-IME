更新日期：2026-10-25。這份文件記錄已實作的方向及待驗證事項；目前操作與結構分別以 [使用指南](USAGE.md) 和 [架構文件](ARCHITECTURE.md) 為準。分支差異見 [文件索引](README.md)。

## 設計方向

沿用微軟注音使用者熟悉的整句組字、回頭選字與中英切換，將詞庫、按鍵規則、候選窗及個人學習維護放在可檢查的原始碼中。比較重點是 E-IME 要提供的調整能力，不以未經驗證的競品內部實作或更新頻率作為設計前提。

## 合併功能分支前優先處理

| 項目 | 完成條件 |
| --- | --- |
| 換機詞庫路徑 | 清理初始化中的個人開發目錄保底，測試只依安裝器寫入的資料路徑；缺詞庫及載入失敗應有可觀察的診斷。 |
| 初始化降級 | 目前可在資料缺失時建立服務；需明確區分「服務建立成功」與「詞庫可用」，避免只看到注音卻無錯誤資訊。 |
| 修飾鍵與逗號 | 實體鍵盤分別測左右 Ctrl／Shift、持續按住、放開、切換焦點及遠端輸入；確認事件快照與即時鍵態混用沒有誤判。 |
| 四欄與模式提示 | 多螢幕、不同縮放、螢幕邊緣及長候選字實機驗證；確認提示消失與後續候選顯示互不干擾。 |
| 語境修正 | 增加人工搭配規則的正／反例語料，量測錯改率；目前每位置單一路徑的評分不能代表完整 bigram 最優搜尋。 |
| 安裝與移除 | 在乾淨帳號確認語言清單自動加入及警告後的手動流程，驗證停用、重新啟用與解除註冊。 |

2026-10-25 本機的 5 組 CTest 已通過；上表是尚需實機或更完整覆蓋的驗收工作，不以單元測試通過替代。

## 後續可評估

- **詞庫維護與隱私**：獨立的個人詞庫位置、編輯及匯出方式，減少誤提交追蹤檔案的機會。
- **學習漫遊**：真實跨機雲端傳輸、衝突副本及長期 writer 檔案累積的行為與效能。
- **語境模型**：先建立可重現的句子評估集，再決定擴充規則或使用具有前詞狀態的搜尋／統計模型。
- **顯示與設定**：高 DPI、字級與布局設定；DirectWrite／Direct2D、深色主題都仍是評估方向，不是已完成功能。
- **架構與排列**：32 位元應用、更多注音排列，以及其他作業系統外殼，均需另行設計與測試。

效能主張應附硬體、建置模式、測試輸入與原始輸出；舊文件中的固定記憶體、冷啟動或「一秒部署」數字不能當作跨裝置保證。
